# 涂层线扫 · 质检台

纯前端 TypeScript + React + Vite，不调用任何业务后端或在线服务；Docker 仅用于发布静态页面。
顶层导航包含三个模块：**第 k 小复核**、**扫描片段接缝** 与 **三段拼接链**。

## 第 k 小复核

涂层线扫仪一次产生约 20 万条强度读数，质检员需同时复核约 10 万个局部窗口的第 k 小值。
逐窗口复制排序的代价约为 Σ 窗口长度·log(窗口长度)，浏览器在换卷前无法给出结论；
本项目使用 **Wavelet Matrix**（16 位值域）将构建降到 O(16n)、每查询降到 O(16)，
满规模实测约 **120 ms**（要求 4 秒内，见 `src/fullscale.test.ts`）。

### 可选：中位绝对偏差总量

质检员发现某些窗口的第 k 小读数虽正常、整段读数却波动很大，可勾选
「同时核对中位绝对偏差总量」：

- 对每个半开窗口取**较低中位数**（排序后第 ⌈len/2⌉ 小；偶数长取两个中位值中
  较小者），精确计算窗口内全部读数到该值的绝对差之和
  Σ|reading − median|；
- 与第 k 小结果**按原查询顺序逐行并排展示**，并给出偏差总量合计；
- 计算复用同一张 Wavelet Matrix 的分层数据组织（每层额外的值前缀和），
  与第 k 小同一次逐层下降 O(16)，**不为任何窗口复制排序**；
- 全部为精确整数（Float64Array 承载 ≤ 13,107,000,000 的层前缀和，
  合计 ≤ 1.31×10¹⁵ < 2⁵³），表格与 CSV 导出均不经 `toFixed`/科学计数，
  重复读数、中位数相等、单元素窗口（总量为 0）、最大合法总量均不溢出、不舍入；
- 未勾选时既有第 k 小结果、摘要与接缝/三段拼接流程逐位保持原样；
  勾选/取消是对**同一份已校验输入**整体重算，新文件载入或查询失败会整体替换
  视图，统计、摘要、表格与导出不可能混用两份数据。

结果区提供「导出 CSV」按钮：列与屏幕表格同源同序，勾选时额外含 `mad_total`
列（含 UTF-8 BOM，整数原样写出）。

## 扫描片段接缝

质检员从本地 JSON 入口分别选择**有方向的前段与后段**两个文件，求
「前段后缀 ≡ 后段前缀」的最大严格相等长度（接缝重叠长度）。
反向相等、内部重复、未接触两端的相似段都不算接缝。

- 文件仍按下述 `readings` / `queries` 契约**整体验证**（queries 非法同样拒收），
  但本模块只读取 `readings`，不调用查询分析，也不渲染既有结果表；
- 双槽位状态机：空闲 → 单侧已载入 → 双侧匹配中 → 接缝成立 / 无重叠；
  替换任一侧立即撤销旧结论并重算；单侧读取或校验失败只标记该槽、保留另一侧；
- **前置流水线与匹配享有同一套数据保护**：读取后的解析与整体验证经调度器排队执行，
  续体入口核验槽位版本——槽位被替换后旧文件的解析/校验在下一调度点自行终止，
  不 parse、不校验、不拖慢新文件，也不得改变另一槽位或最近合法结论；
  超过 16 MiB 的文件在读取前拒绝，校验诊断有 50 条上限；
- 匹配核心为 **KMP 前缀函数**（`src/seam/seamCore.ts`）：线性时间、O(|right|) 辅助空间，
  按可中断分片推进，每个分片延续由值域外哨兵（-1）界定的前缀函数状态；
- 匹配任务以**双侧版本身份**（leftVersion / rightVersion / taskId）绑定：
  替换后旧任务在下一调度点自行终止，晚到的完成回调不得覆盖当前状态，
  匹配期间界面仍可继续选择文件；
- 结果区展示两侧文件名、重叠长度、去重拼接长度（|left|+|right|−overlap），
  以及前段末尾、后段开头各至多 8 条读数，接缝部分高亮。

## 三段拼接链

涂层线扫仪把同一卷读数分成三份上传，质检员在**不知道三份先后次序**时需要
可复核的完整拼接链。独立的三槽位工作区（槽位 A / B / C，与双槽接缝互不影响）：

- 每槽仍按 `readings` / `queries` 契约**整体验证**（queries 非法同样拒收），
  但只把 `readings` 交给拼接服务；超过 16 MiB 的文件在读取前拒绝；
- 三份均有效后枚举全部 3! = 6 种有向顺序：逐次以**当前合成序列的后缀**与
  下一份的前缀求最大严格相等重叠（复用 KMP 接缝核心），每道接缝
  **至少重叠 1 条读数**，且下一份**至少贡献 1 条新读数**（重叠不得把下一份
  整个吸收）；
- 合法方案中取**合成长度最短**（三份条数之和 − 两道接缝重叠）者；
  完全并列时按**槽位名称 A→B→C 顺序**裁决（排列按字典序枚举、严格更短才替换）；
- 结果区展示最终顺序（槽位 + 文件名 + 条数）、两道接缝长度、合成长度，
  以及合成序列开头/末尾各至多 8 条读数的合成预览；
  六种顺序均不合法时明确说明无合法拼接顺序；
- 三槽位状态机：空闲 → 部分就绪 → 匹配中 → 拼接成立 / 无合法顺序；
  **替换、读取失败或取消任一槽位**立即撤销旧结论并作废在途任务，
  链式任务以三槽版本身份（versionA/B/C + taskId）绑定，迟到的解析与匹配
  结果在下一调度点自行终止，绝不混入新文件；
- 链式匹配同样按可中断分片推进（含合成序列的分片物化），
  满规模（3 × 20 万）处理元素总数有确定性上界并锁定精确值
  （见 `src/chain/chainFullscale.test.ts`）。

## 输入文件格式

JSON，仅含两个键：

```json
{
  "readings": [120, 0, 65535, 88],
  "queries": [{ "start": 0, "end": 3, "k": 1 }]
}
```

- `readings`：整数数组，长度 1..200000，每个值 0..65535；
- `queries`：对象数组，至多 100000 个，每个对象仅含 `start`、`end`、`k` 三个整数；
- 区间按半开 `[start, end)` 解释，须满足 `0≤start<end≤readings.length` 且 `1≤k≤end-start`。

任何结构或边界错误都会**拒绝整个文件**：页面按数组下标（如 `queries[317]`、`readings[12]`）
列出错误，清除旧结果，且不会留下任何部分答案。为防止误选超大文件时诊断与渲染随输入长度
线性膨胀：**超过契约规模的数组不再逐元素遍历**（只报长度错误）；合法规模内的逐条错误
至多展示 50 条可定位诊断，其余折叠为单条「错误过多」摘要；超过 16 MiB 的文件在读取前
（文本尚未进入内存）直接拒绝。

## 页面行为（第 k 小复核）

- 选择 JSON 文件（全程仅本机读取），或点击「载入内置满规模样本」生成确定性满规模数据；
- 成功后按**原查询顺序**逐行展示查询下标、start/end/k、窗口长度与精确第 k 小值；
  勾选「同时核对中位绝对偏差总量」后，每行并排展示较低中位数对应的
  精确 Σ|读数−中位数|，摘要区追加偏差总量合计，并可导出含/不含 `mad_total`
  两版同源 CSV；
- 结果表采用窗口化渲染，10 万行不卡顿，并提供首行/末行跳转；
- 展示计算耗时、答案总和与 FNV-1a 摘要，供质检员核对。

## 测试策略（Vitest）

- `src/core.test.ts`：以**直接排序**为小样本预言机，对全部子区间与全部 k 穷举比对，
  覆盖重复值、全相等、单元素、首尾窗口及 k 的两端；并覆盖全部拒绝路径；
- `src/madCore.test.ts`：中位绝对偏差总量的独立预言机（**直接排序取较低中位数 +
  逐项绝对差求和**），对全部子区间穷举，覆盖单元素窗口（总量 0）、全相等、
  偶数长较低中位（两中位值不等）、重复读数、0/65535 混排，以及 20 万长窗口
  最大合法总量（10 万个 65535，6,553,500,000；奇/偶长两例）的精确性与无溢出；
  并核对未启用时结果形状不变、启用后与第 k 小同序、空查询、失败不留任何总量；
- `src/kthReview.browser.test.tsx`（jsdom + Testing Library）：浏览器层面对照
  预言机逐行核对**切换文件后**表格与 CSV 导出逐字节一致（含 BOM），覆盖
  开关两态、单元素 0 值列、非法文件整体清除（错误态无导出入口）、再载合法
  文件不混入旧数据，以及满规模样本屏幕首行与导出首行同源；
- `src/fullscale.test.ts`：固定种子生成确定性满规模样本（20 万 / 10 万），
  断言 `analyze` 在 **4000 ms** 内完成，且 `sum` / FNV-1a `digest` 与锁定常量一致，
  首尾窗口与相邻窗口再与直接排序逐项核对，防止下标偏移；启用 MAD 时同样
  4 秒内完成、不改变既有答案，并锁定 `madSum` 精确常量（175,427,861,514），
  抽查窗口的总量与较低中位数再对直接排序 + 逐项求和预言机；
- `src/seam/seamCore.test.ts`：以**朴素后缀-前缀比对**为预言机核对随机小样本，
  并覆盖周期、全同、包含、单元素、零重叠、反向相等与内部重复等陷阱，
  验证任意分片预算与一次性计算结果一致；
- `src/seam/seamStore.test.ts`：用**可控手动调度器**精确交错分片，
  证明替换或单侧失败时旧任务在下一调度点终止、晚到回调不回写旧结果，
  并覆盖文件读取/解析/契约失败与晚到的文件回调；
- `src/validationCap.test.ts`：构造超长 readings/queries（百万级）与海量非法元素，
  断言超规模数组不逐元素遍历（错误条数与耗时均有界）、错误摘要至多 50 条下标诊断
  +1 条截断说明，且 200000/100000 的合法上限文件与 queries 整体验证保持兼容；
- `src/seam/seamGuard.test.ts`：构造「读取中被替换」的大文件（可控 parse 间谍 +
  延迟读取），断言旧续体不 parse/不校验、调度队列无残留、槽位留在新文件、
  另一槽位与最近接缝结论不被污染、晚到拒绝回调被忽略，并覆盖 16 MiB
  读取前字节闸门（边界两侧）；
- `src/seam/seamFullscale.test.ts`：双侧各 20 万条的确定性满规模验收，
  以截断器值锁定精确重叠长度，断言去重拼接长度、两侧上下文、
  处理元素总数恰为 (|right|−1)+|left|（线性工作量）且 1 秒内完成。
- `src/chain/chainCore.test.ts`：以**短数组暴力枚举**六种顺序为预言机，
  对随机小样本与嫁接样本逐一比对，覆盖重复读数（全同/周期数据）、
  并列最优（三种顺序合成长度相同，取槽位名称字典序最小者）、
  无解（互不重叠、完全吸收、两两可接但串不成链）与接缝约束边界，
  并验证任意分片预算与一次性裁定一致、合成预览是合成序列的头尾；
- `src/chain/chainStore.test.ts`：用可控手动调度器精确交错分片，
  证明替换、失败或取消任一槽位时旧任务在下一调度点终止、
  晚到回调不回写旧结果，并覆盖快速换文件（迟到读取不解析、不混入）；
- `src/chain/chainFullscale.test.ts`：三槽各 20 万条的确定性满规模验收，
  以互不相交值域 + 植入重叠区锁定精确的两道接缝长度与唯一合法顺序，
  断言合成长度、处理元素总数精确值（线性工作量）且 2 秒内完成。

## Docker Compose 发布

```bash
docker compose up web                 # 默认 http://localhost:8080
WEB_PORT=9000 docker compose up web   # 覆盖宿主端口
docker compose build verify
docker compose run --rm verify        # 一次性验收：运行完整 Vitest，exit 0 即通过
```

`web` 为 nginx 托管的纯静态页面；`verify` 不常驻、不映射端口，专门用于换卷前/发布前验收。
